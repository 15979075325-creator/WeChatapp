# 课间牌局

一款微信小游戏。你和电脑各拿 7 张牌，按颜色、数字或功能图案接牌，先出完手牌的一方获胜。游戏离线运行，无需安装 npm 包或配置云服务。

## 在电脑或手机上玩

1. 在微信开发者工具选择「小游戏 → 导入」。
2. 目录选到能直接看到 `game.js`、`game.json` 和 `project.config.json` 的那一层。克隆仓库时选仓库根目录。
3. 选择自己的 **小游戏 AppID**，可使用「小游戏测试号」。后端选「不使用云服务」。
4. 点击「编译」，看到牌桌后点「预览」，用有权限的手机微信扫码。

带「可出」字样的手牌可以打出；没有可出的牌时，摸一张并结束回合。⊘ 跳过对方，+2 让对方抽牌并跳过，✦ 可以改变桌面颜色。手牌栏右侧的箭头用来翻页。

## 项目结构

```text
campus-cards-minigame/
├─ game.js               # 小游戏入口、画牌桌、处理点击和回合
├─ rules.js              # 洗牌、发牌、功能牌、电脑决策、胜负
├─ game.json             # 微信小游戏运行设置
├─ project.config.json   # 开发者工具项目设置
├─ .gitignore            # 忽略个人工具配置和本地临时文件
├─ README.md             # 玩法、导入和目录说明
└─ ROADMAP.md            # 三人分工、开发顺序、验收和演示
```

当前只有两个 JavaScript 文件，共 **333 行**：`game.js` 198 行、`rules.js` 135 行，含空行。第一版已经能发牌、与电脑对战、结算并再开一局；本地战绩、难度选择和动画是后续任务。

代码从 `game.js` 启动：点击手牌后，它让 `rules.js` 判断能不能出牌、更新牌局，再把新状态画到屏幕上。规则不用关心按钮长什么样，牌桌也不用自己判断胜负。

## 三人怎么继续

- **成员 A：** 牌桌和触控，负责 `game.js` 里的页面接线。
- **成员 B：** 出牌规则和电脑难度，负责 `rules.js`。
- **成员 C：** 结算、战绩和真机验收，新增 `stats.js`，和成员 A 约定界面入口。

具体顺序和验收标准见 [ROADMAP.md](ROADMAP.md)。开发者工具可能会把个人 AppID 写入项目配置；提交前检查变更，仓库里的 `project.config.json` 应继续保留通用配置。
